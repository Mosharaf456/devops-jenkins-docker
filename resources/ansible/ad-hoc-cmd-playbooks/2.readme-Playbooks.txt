1. Host Key Changed
The error shows that the host key for some servers (e.g., 192.168.1.101) has changed. This usually happens when:

The server has been reinstalled.
The SSH key on the server was regenerated.
You're connecting to a different server at the same IP address.

What is the default module used in an ad hoc command if no module is specified explicitly?

= by setting the --become option

= --extra-vars

Tasks:
1. Set up a basic Ansible inventory with managed nodes.
2. Run ad hoc commands to gather information about managed nodes.
3. Perform system maintenance tasks using ad hoc commands.
4. Explore and utilize different modules in ad hoc commands.

1. Set up a Basic Ansible Inventory with Managed Nodes
Ansible uses an inventory file (hosts.ini) to define managed nodes.
Create an inventory file (hosts.ini):host.ini 
[web]
web1 ansible_host=192.168.1.10 ansible_user=root
web2 ansible_host=192.168.1.11 ansible_user=root

[db]
db1 ansible_host=192.168.1.20 ansible_user=root

Verify connectivity with the managed nodes:
> ansible all -i hosts.ini -m ping



2. Run Ad Hoc Commands to Gather Information About Managed Nodes
Check system uptime:
> ansible all -i hosts.ini -m command -a "uptime"

Get OS details:
> ansible all -i hosts.ini -m setup | grep "ansible_distribution"

Check free disk space:
>ansible all -i hosts.ini -m shell -a "df -h"




3. Perform System Maintenance Tasks Using Ad Hoc Commands

Update package lists (Debian-based systems):
> ansible all -i hosts.ini -m apt -a "update_cache=yes" --become

Install htop on all nodes:
> ansible all -i hosts.ini -m package -a "name=htop state=present" --become

Restart a service (e.g., Apache):
> ansible web -i hosts.ini -m service -a "name=apache2 state=restarted" --become

Reboot all nodes:
> ansible all -i hosts.ini -m reboot --become



4. Explore and Utilize Different Modules in Ad Hoc Commands
Copy a file to all nodes:
> ansible all -i hosts.ini -m copy -a "src=/etc/hosts dest=/tmp/hosts" --become

Check user existence:
> ansible all -i hosts.ini -m command -a "id ansible"

Create a new user:
> ansible all -i hosts.ini -m user -a "name=deploy state=present" --become

Change file permissions:
> ansible all -i hosts.ini -m file -a "path=/var/www/html mode=0755 state=directory" --become

Fetch a file from remote nodes:
> ansible all -i hosts.ini -m fetch -a "src=/etc/passwd dest=./backup/" --become

node1 ansible_host=192.168.1.101

Use the ping module to check if the managed nodes are accessible and responding to Ansible. Run the following command:

ansible all -i hosts -m ping

ansible all -i hosts -m setup

Use the yum module to update packages on the managed nodes. Run the following command:

ansible all -i hosts -m yum -a "name=* state=latest" --become
Use the file module to create a directory on the managed nodes. Run the following command:

ansible all -i hosts -m file -a "path=/tmp/mydir state=directory" --become

Refer to the Ansible documentation to discover more modules and their usage in ad hoc commands. Try running additional ad hoc commands with different modules to perform various tasks on your managed nodes.

Alternative Approach Using systemctl
For systems with systemd, you could replace pgrep with:
---
    - name: Check if SSH service is active
      shell: systemctl is-active ssh
      register: ssh_status
      ignore_errors: yes

    - name: Start SSH service if not active
      service:
        name: ssh
        state: started
      when: ssh_status.stdout != "active"
